# P0-01 — Études de cas : portfolio et pipeline vidéo

## Ce qui a été fait
- `docs/portfolio/etude-de-cas-portfolio.md` : étude de cas du portfolio et de son assistant Mistral, écrite à partir du code (`src/pages/api/mistral.page.ts`, `src/lib/assistant-context.ts`, `supabase/security-hardening-2026-09.sql`, `vercel.json`).

- Format commun : Problème → Approche → Architecture (Mermaid) → Résultats vérifiables → Démo → Stack → Limites et suite.

## Pourquoi ce choix plutôt que l'alternative courante
L'alternative courante est une fiche projet « vitrine » : liste de technologies et adjectifs. Elle ne dit pas quel problème est résolu ni ce qui est prouvé. Le format étude de cas force à séparer ce qui est **implémenté** (lisible dans le code), ce qui est **en ligne** (URL vérifiée) et ce qui est **mesuré** (rien pour l'instant). C'est ce qu'un responsable d'équipe IA vérifie en entretien. La section « Limites » montre que les faiblesses sont connues et relie le portfolio au projet en cours (Studeria Assistant).

## 5 questions d'entretien
1. **Pourquoi le prompt système de l'assistant est-il construit côté serveur et pas envoyé par le navigateur ?**
   Si le navigateur envoyait le prompt système, n'importe qui pourrait appeler `/api/mistral` avec ses propres instructions et utiliser la clé pour un tout autre usage, à mes frais. Côté serveur, le client n'envoie que l'historique ; le contexte vient de Supabase, limité aux données publiées.
2. **Comment la clé Mistral est-elle protégée ?**
   Elle n'existe que dans une variable d'environnement serveur (`MISTRAL_API_KEY`), jamais préfixée `NEXT_PUBLIC_` (ces variables sont incluses dans le JavaScript envoyé au navigateur). Le proxy ajoute une vérification d'origine, une limite de requêtes par IP et des bornes sur la taille des messages et des réponses.
3. **Pourquoi une chaîne de modèles plutôt qu'un seul modèle ?**
   Un modèle peut être hors forfait ou en dépassement de quota. Sur les erreurs 403, 429 ou 5xx, la route bascule sur le modèle suivant : l'assistant reste disponible au prix d'une qualité éventuellement un peu moindre. Sur une erreur 400 (requête invalide), changer de modèle ne servirait à rien, donc on s'arrête.
4. **Quelle est la limite principale de cet assistant, et comment la corrigerais-tu ?**
   Il n'est pas évalué : rien ne mesure s'il invente un fait. Je construirais un jeu de questions avec réponses de référence, des questions hors contenu pour tester l'abstention, et un score suivi en CI — c'est le cœur du projet Studeria Assistant.
5. **Pourquoi l'étude de cas du pipeline vidéo ne contient-elle ni chiffre ni lien ?**
   Il n'a pas de dépôt public ni de mesure publiée. Écrire un chiffre non vérifiable ferait perdre la confiance sur tout le reste du portfolio. La suite logique est de publier une version nettoyée avec une démo.
